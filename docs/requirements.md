# Valkeep 요구사항

> 이 문서는 목표 요구사항이며 모든 항목의 구현 완료를 의미하지 않는다. 현재 구현 및 미검증 범위는 [구현·실행 안내](implementation.md)에 기록한다.

## 1. 목적

AI 클라이언트가 운영 Redis의 상태와 데이터를 조사할 수 있도록 하면서, 데이터 변경을 차단하고 과도한 조회·민감정보 노출 위험을 줄인다.

공식 Redis MCP의 기능을 그대로 모두 노출하는 대신, **검토된 도구와 요청만 공식 MCP로 전달하는 정책 프록시**를 제공한다.

이 문서의 `필수`는 구현 및 수용 테스트에서 만족해야 하는 조건이며, `제안`은 대상 환경 확인 후 조정할 기본 방향이다.

## 2. 배경과 문제

공식 Redis MCP의 조사 당시 구현에는 다음 특성이 있었다.

- `scan_keys`는 SCAN 한 번을 실행하지만 `count`의 최대값을 강제하지 않는다.
- `scan_all_keys`는 전체 순회를 완료할 때까지 반복하고 결과를 메모리에 누적한다.
- `hgetall`, `smembers`는 컬렉션 전체를 조회한다.
- `lrange`, `zrange`는 호출자가 전달한 범위를 그대로 사용한다.
- 연결 풀 제한은 존재하지만, 조회 요청의 rate limit·전체 탐색 예산·응답 크기를 일괄 제한하는 정책은 확인되지 않았다.

따라서 read-only 계정만 연결하는 것으로는 운영 부하와 정보 노출을 충분히 통제할 수 없다. 반대로 모든 조회 기능을 새로 구현하는 것은 공식 구현 재사용이라는 목적과 맞지 않는다.

근거와 재검증 대상은 [설계 문서의 참고 자료](design.md#12-참고-자료)에 정리한다. 조사 결과는 특정 릴리스의 검증 완료를 의미하지 않는다.

## 3. 사용 사례

### 포함

- 여러 Redis target을 한 MCP에 등록하고, 조회할 target을 명시적으로 선택.
- 알려진 키의 타입·밀리초 TTL·타입별 길이/개수 확인.
- 기본 안전 프리셋과 기능별 명시적 활성화.
- String의 제한된 바이트 미리보기 및 PING 연결 점검.
- 필요한 ACL 권한안 생성과 관리자 export의 오프라인 정책 일치 검사.
- 허용된 범위 내 키 탐색.
- 컬렉션 내용 조회는 큰 원소의 바이트 비용을 통제할 수 있을 때만 후속 범위로 검토한다. 현재는 String 미리보기만 지원한다.
- 거절된 요청의 사유와 제한된 조회의 일부 결과 여부 확인.
- 운영자가 어떤 대상에 어떤 종류의 조회가 수행되었는지 감사.

### 초기 범위에서 제외

- 데이터 생성·수정·삭제, TTL 변경, DB flush, 설정 변경.
- 임의 Redis 명령, Lua 스크립트, Redis Functions 실행.
- 전체 키 덤프, 무제한 컬렉션 조회, 자동 전체 순회.
- Pub/Sub, consumer group 조회 등 구독이나 상태 변경을 동반할 수 있는 기능.
- Redis Cloud 리소스 생성·관리와 같은 관리 API.
- 조회 결과에 기반한 자동 복구·자동 수정.
- SQL·MongoDB 등 Redis 외의 DB 엔진 지원. 여러 Redis target 등록은 포함한다.
- 다중 사용자 원격 서비스, 수평 확장, Cluster 전체 탐색은 별도 검증 전까지 초기 범위에서 제외한다.

## 4. 신뢰 경계와 보장 범위

### 가정

- AI가 만든 도구 이름, 인자, 키, 패턴, cursor는 모두 검증 대상이다.
- Redis 값과 업스트림 응답은 데이터일 뿐이며 정책 변경 지시로 해석하지 않는다.
- 운영자 관리 설정은 신뢰하지만 클라이언트 도구 인자로 수정할 수 없다.
- Redis ACL은 올바르게 구성되어 있고, MCP 계정에는 불필요한 권한이 없다.
- 공식 MCP와 의존 패키지는 버전을 고정하고 검토한다. ACL은 업스트림 오류·취약점에 대한 추가 방어다.

### 보장할 것

- 허용되지 않은 도구·인자·대상에 대한 요청은 Redis 호출 전에 거절한다.
- 도구 목록에서 숨긴 기능을 이름으로 직접 호출해도 실행할 수 없다.
- 쓰기는 Redis 계정 권한으로 거절한다.
- 프록시를 통과하는 요청에 대해 설정한 호출·동시 실행·누적 탐색 예산을 강제한다.

### 보장하지 않는 것

- 운영 Redis의 지연시간과 처리량에 영향이 전혀 없다는 보장.
- 반환 개수만으로 실제 CPU·네트워크 비용을 정확히 제한하는 것.
- 클라이언트 timeout 발생 시 Redis의 실행 중인 명령을 강제로 중단하는 것.
- ACL 키 패턴만으로 SCAN에 의한 키 이름 열거를 숨기는 것.
- 자격증명을 직접 사용할 수 있는 동일 OS 사용자나 운영자의 의도적 우회 방지. 로컬 stdio 배포는 강한 사용자 간 보안 격리가 아니다.
- 변경 중인 Redis 데이터에 대한 원자적 스냅샷 또는 전체 탐색 완전성.

## 5. 기능 요구사항

### FR-01. 도구 허용 목록 — 필수

- 검토한 도구만 클라이언트의 `tools/list`에 노출한다.
- `tools/call`에서도 동일한 허용 목록을 재검사한다.
- 새로운 업스트림 도구는 자동으로 허용하지 않는다.
- 모든 이름·별칭은 명시적 매핑을 거친다. 임의 업스트림 호출 도구를 제공하지 않는다.

### FR-02. 인자 검증 — 필수

- 타입, 정수 범위, 문자열 길이, 필수 필드, 추가 필드 여부를 검증한다.
- 범위 조회는 음수 인덱스를 초기 정책에서 거절하고, `0 ≤ start ≤ stop` 및 최대 반환 항목 수를 검사한다.
- `count`와 페이지 크기에 상한을 둔다.
- 숨은 기본값이 전체 조회로 확장되지 않도록 업스트림에 검증된 인자를 명시적으로 전달한다.

### FR-03. 키·대상 접근 제한 — 필수

- 연결 대상 목록은 프로세스 설정으로만 지정한다. 조회 도구는 등록된 `target_id`를 필수로 받되, endpoint·계정·DB를 직접 변경할 수 없다.
- 키 접근은 명시적인 허용 prefix 또는 exact key 정책을 따른다.
- 키 탐색 시 사용자가 임의 glob 패턴을 입력하지 않게 한다. 허용 prefix 식별자를 선택하면 서버가 안전하게 패턴을 생성한다.
- SCAN 결과도 허용 범위로 다시 필터링한다.
- 이 정책은 Redis 내부의 탐색 범위를 해당 prefix만으로 제한하지는 않는다.

### FR-04. Redis ACL — 필수

- 전용 계정에 필요한 명령만 허용한다. 단순히 `+@read` 전체를 허용하는 구성을 기본값으로 삼지 않는다.
- 데이터 변경, 관리 명령, 스크립트, 기능 실행 권한을 부여하지 않는다.
- 연결 준비에 필요한 명령은 선택한 Redis client와 배포 환경에서 확인하여 최소한으로 추가한다.
- 키 범위는 가능한 경우 Redis ACL에서도 제한한다. 프록시의 키 정책과 함께 적용한다.
- 운영 쓰기 차단 검증을 위해 실제 운영 키에 쓰기 요청을 보내지 않는다. 테스트 환경 및 지원되는 ACL 검사 기능으로 검증한다.

### FR-05. 호출 및 작업 예산 — 필수

- 대상 단위 rate limit과 최대 동시 업스트림 호출 수를 적용한다.
- 첫 버전은 대기열 없이 초과 요청을 거절하는 방식을 제안한다.
- SCAN은 페이지별 호출 횟수, 탐색 세션의 누적 호출 횟수·시간·관측 키 수 예산을 적용한다.
- 빈 페이지도 예산을 소비한다. cursor를 새로 시작해도 대상 단위 rate limit을 우회할 수 없다.
- 클라이언트가 응답 대기를 취소해도 실제 업스트림 호출이 종료되기 전에는 실행 슬롯을 반환하지 않는다.

### FR-06. 결과 크기 및 부분 조회 — 필수

- 클라이언트 반환 바이트·항목 수에 상한을 둔다.
- 결과를 자른 경우 `truncated` 등 구조화된 메타데이터로 알린다.
- 전체 조회 완료와 예산 소진, 반환 크기 초과, 조회 오류를 구분한다.
- 큰 값을 가져온 뒤 자르는 방식은 클라이언트 보호일 뿐 Redis 부하 제한이 아님을 명시한다.
- 안전한 사전 제한이 불가능한 도구는 차단하거나 별도의 제한된 조회 방식으로 대체한다.
- SCAN COUNT는 엄격한 결과 개수·바이트 제한이 아니므로 한 페이지도 예상 크기를 초과할 수 있음을 문서화한다.

### FR-07. 정책 불변성 — 필수

- 클라이언트가 도구 호출로 정책을 완화하거나 제한을 초기화할 수 없다.
- 초기 버전의 정책 변경은 운영자가 설정을 변경하고 프로세스를 재시작하는 방식으로 제한한다.
- 시작 시 정책 구조·필수 값·모순을 검증하고, 잘못된 정책으로는 서비스를 시작하지 않는다.

### FR-08. MCP 경계 — 필수

- 업스트림 `resources`, `prompts`, 알림 또는 서버 주도 요청을 무조건 전달하지 않는다.
- 초기 버전은 필요한 MCP 수명주기와 검토된 tools 기능만 제공한다.
- 업스트림이 클라이언트에 sampling, elicitation 등의 요청을 보내도 별도 설계 없이 전달하지 않는다.
- 업스트림 도구 설명을 그대로 신뢰하거나 시스템 지시로 사용하지 않는다. 공개 설명과 스키마는 Valkeep이 관리한다.

### FR-09. 감사·관측 — 필수

- 대상 식별자, 요청 ID, 정책 버전, 도구명, 허용/거절 결과, 지연시간, 반환 크기, 종료 사유를 기록한다.
- 원본 Redis 값·비밀번호·접속 URL·원본 키를 기본 로그에 남기지 않는다.
- 키 식별이 필요하면 일반 해시 대신 비밀키 기반 HMAC 등 추측 공격을 고려한 방식으로 가명화한다.
- 업스트림 stderr와 오류 메시지도 민감정보 유출 대상으로 취급하고 정제한다.

### FR-10. 버전 호환성 — 필수

- 공식 MCP 버전, 의존성 및 실행 산출물 식별자를 고정한다.
- 시작 시 필요한 업스트림 도구와 입력 스키마가 검증된 계약과 일치하는지 검사한다.
- 필요한 계약이 달라지면 시작을 거절한다. 추가된 미허용 도구는 노출하지 않고 기록한다.
- 출력 형식과 실제 Redis 명령은 릴리스별 테스트로 검증한다. 스키마 비교만으로 실행 의미의 호환성을 보장하지 않는다.

### FR-11. 다중 target — 필수

- `policy_version = 2`의 `targets` 목록에 1~16개 대상을 등록한다. 기본 target·이름 추정·교차 대상 재시도를 제공하지 않는다.
- target ID 중복, 동일 host/port/database의 중복 등록, 감사 파일 경로 충돌을 거절한다.
- target별 연결·자격증명·허용 도구·키 범위·호출 예산·감사 로그·업스트림 프로세스를 분리한다.
- 한 target의 실행 중 지연·호출 제한·감사 실패가 다른 정상 target의 실행을 차단하지 않아야 한다.
- 시작 단계에서 설정·자격증명·업스트림 초기화 중 하나라도 실패하면 이미 시작한 대상도 정리하고 서버를 공개하지 않는다.
- 라우터 공통 감사 기록 실패는 모든 target의 새 조회를 차단한다.
- `list_targets`는 ID·환경·허용 도구·로컬 프록시 상태만 반환한다. host·계정·비밀번호·환경변수 이름·키 prefix는 반환하지 않는다.
- `list_targets`는 Redis에 명령을 보내지 않는다. 업스트림 계약 검증 상태를 Redis 연결 정상 상태로 표현하지 않는다.
- 등록된 모든 target은 동일 MCP 사용자가 접근할 수 있다. 사용자별 target 권한 분리는 원격 서비스화 시 별도 요구사항이다.
- 미래의 탐색 토큰에도 target ID를 결합하여 다른 target에서 재사용하지 못하게 한다.

### FR-12. 사용하기 쉬운 기본 정책과 진단 — 필수

- production-safe는 메타데이터·연결 점검만 허용한다. 미리보기·키 탐색은 각각 명시적으로 활성화한다.
- 프리셋에서는 호출률·동시 실행·탐색 예산의 보수적 상한을 강제한다.
- 미리보기는 String의 GETRANGE로 실제 읽는 바이트를 제한하고, 그 외 타입을 전체 조회로 대체하지 않는다.
- 선택한 도구와 키 범위로 최소 ACL 권한안을 생성하되 자동 적용하지 않는다.
- 관리자 ACL export의 활성화·비밀번호 존재·명령·키 범위를 검사하고 추가 selector·채널·초과 권한을 거절한다.
- 오프라인 검증을 현재 실제 계정의 권한 검증으로 표현하지 않는다. 운영 키에 쓰기 시험을 하지 않는다.
- 연결 점검은 별도 명시적 요청으로만 PING을 실행하고 실제 네트워크 접근임을 안내한다.

## 6. 비기능 요구사항

- **예측 가능성**: 자동 전체 순회, 무제한 대기열, 무제한 재시도를 금지한다.
- **실패 시 차단**: 정책 저장소·감사·업스트림 장애 시 동작을 명시한다. 보안 정책 확인 실패는 허용으로 대체하지 않는다.
- **최소 노출**: 가능하면 로컬 stdio로 시작하며, 원격 서비스화 시 인증·인가·TLS를 별도 설계한다.
- **유지보수성**: 공식 서버 fork보다 외부 프록시를 우선한다. 대체 조회 코드는 별도 어댑터로 분리한다.
- **테스트 가능성**: 운영 데이터 없이 큰 키·큰 값·불안정 연결을 합성하여 검증할 수 있어야 한다.
- **성능 목표**: 허용 Redis 지연 증가량, 프록시 오버헤드, 요청량 목표는 대상 baseline 측정 후 확정한다. 임의의 수치를 운영 안전성 보장으로 제시하지 않는다.

## 7. 수용 기준

| ID | 검증 시나리오 | 통과 조건 |
|---|---|---|
| AC-01 | 숨겨진 쓰기 도구 이름으로 직접 호출 | 업스트림 호출 0회, 명시적 거절 |
| AC-02 | 새 업스트림 도구 추가 | 자동 노출·실행되지 않음 |
| AC-03 | 범위 `0, -1`, 과도한 count, 추가 필드 전달 | 업스트림 호출 전에 거절 |
| AC-04 | 허용되지 않은 prefix·glob 메타문자·임의 cursor 전달 | 정책에 따라 거절, 범위 우회 불가 |
| AC-05 | 빈 SCAN 페이지 연속 반환 | 호출 예산 소진 후 중단 |
| AC-06 | 같은 탐색 토큰을 동시·반복 사용 | 중복 실행 및 예산 우회 방지 |
| AC-07 | 호출 빈도·동시 실행 초과 | 설정된 상한 준수, 무제한 대기 없음 |
| AC-08 | timeout 후 업스트림 지연 지속 | 종료 확인 전 실행 슬롯 재사용 없음 |
| AC-09 | 단일 큰 값·큰 컬렉션 조회 | 도구 정책에 따라 차단 또는 제한된 명령 사용; 사후 절단을 사전 제한으로 표시하지 않음 |
| AC-10 | 큰 SCAN 페이지·중복 키·조회 중 삭제 | 결과 제한과 부분 조회 상태를 올바르게 반환 |
| AC-11 | 로그·오류·업스트림 stderr 검사 | 자격증명·원본 값·기본 설정의 원본 키가 노출되지 않음 |
| AC-12 | 잘못된 정책·필수 스키마 불일치 | 준비 완료 상태가 되지 않고 시작 실패 |
| AC-13 | 테스트 계정으로 쓰기·관리·스크립트 시도 | Redis ACL에서 거절 |
| AC-14 | 업스트림 resources·prompts·서버 주도 요청 | 승인되지 않은 기능은 중계되지 않음 |
| AC-15 | Redis 장애·클라이언트 연결 종료 | 성공/빈 결과로 오인하지 않고 명시적 상태 및 자원 정리 |
| AC-16 | target 생략·미등록 ID | 모든 업스트림 호출 0회, 기본 대상 선택 없음 |
| AC-17 | target A의 키·도구 권한을 B에서 사용 | B의 정책으로 거절, A로 자동 재시도하지 않음 |
| AC-18 | A 호출 중 지연·제한·감사 실패 | 정상 B의 조회는 성공 |
| AC-19 | 두 target 동시 조회 | 서로 다른 자식 프로세스로 전달, 자격증명·응답·감사 대상 일치 |
| AC-20 | 일부 target 초기화 실패·전체 종료 | 시작한 자식과 감사 파일 핸들 정리 |
| AC-21 | 중복 ID·endpoint·감사 경로 | 설정 검증 단계에서 거절 |
| AC-22 | target 목록 조회 | Redis 호출 없이 메타데이터만 반환, 연결 정보 미노출 |
| AC-23 | production-safe 기본 설정 | 값 미리보기·탐색 미노출, 높은 호출 제한값 거절 |
| AC-24 | 큰 String·바이너리 값 | GETRANGE 한도 준수, 안전한 UTF-8/base64 표현 |
| AC-25 | ACL 권한안·export 검사 | 권한 변경 없음, 초과 권한 거절, 비밀번호 해시 미출력 |
| AC-26 | 격리된 실제 Redis 평문/TLS | 조회 성공, 쓰기·관리·범위 밖 접근 및 신뢰되지 않는 인증서 거절 |
